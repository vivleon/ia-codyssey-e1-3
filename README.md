# Mini NPU Simulator

AI가 자주 사용하는 MAC(Multiply-Accumulate) 계산을 Python 기초 문법으로
연습하는 콘솔 프로그램입니다.

이 프로젝트는 실제 NPU 하드웨어를 실행하지 않습니다. Python의 **목록,
딕셔너리, 반복문, 조건문, 함수**를 사용해 NPU의 핵심 계산 원리를 작게
흉내 냅니다.

## 1. 프로그램이 하는 일

프로그램에는 두 가지 모드가 있습니다.

1. 사용자 입력 모드: 3×3 필터 A, 필터 B, 입력 패턴을 직접 입력합니다.
2. JSON 분석 모드: `data.json`의 5×5, 13×13, 25×25 패턴을 분석합니다.

두 모드 모두 다음 순서로 동작합니다.

```text
입력 준비
→ 입력 패턴과 각 필터의 MAC 점수 계산
→ 두 점수 비교
→ 판정과 연산 시간 출력
```

## 2. 실행 방법

Python 3.8 이상만 있으면 됩니다. 외부 라이브러리는 사용하지 않습니다.

```bash
git clone https://github.com/vivleon/ia-codyssey-e1-3.git
cd ia-codyssey-e1-3
python3 main.py
```

메뉴를 거치지 않고 바로 실행할 수도 있습니다.

```bash
python3 main.py --mode user
python3 main.py --mode json
python3 main.py --mode json --data ./data.json --repeats 10
```

자동 테스트 실행:

```bash
python3 -m unittest discover -v
```

### 왜 클래스를 사용하지 않았나요?

이 과제는 데이터베이스나 여러 화면을 가진 큰 프로그램이 아닙니다. 목록과
딕셔너리만으로 행렬과 결과를 충분히 표현할 수 있으므로, 초보자가 실행 흐름을
바로 따라갈 수 있게 작은 함수로 나눴습니다.

- 행렬: `[[1, 0], [0, 1]]` 같은 2차원 목록
- 필터 모음: `{"Cross": 행렬, "X": 행렬}` 딕셔너리
- 분석 결과: 점수, 판정, PASS/FAIL을 담은 딕셔너리

## 4. MAC 연산 기초

MAC은 **Multiply-Accumulate**, 즉 “곱하고 더한다”는 뜻입니다.

입력 패턴과 필터의 같은 위치에 있는 값을 곱한 뒤 모두 더합니다.

```text
입력 패턴      필터
1 0            1 1
0 1            0 1

점수 = 1×1 + 0×1 + 0×0 + 1×1 = 2
```

코드에서는 `npu.py`의 `mac_score()`가 이 계산을 합니다.

```python
total = 0.0
for row in range(size):
    for column in range(size):
        total += pattern[row][column] * filter_matrix[row][column]
return total
```

AI 신경망은 입력값과 가중치를 곱하고 더하는 계산을 매우 많이 수행합니다.
그래서 MAC은 이미지 인식, 신경망의 가중합, 행렬곱 같은 AI 계산의 기초입니다.

### 점수가 높으면 왜 더 유사한가요?

현재 데이터처럼 같은 크기와 같은 범위의 0/1 값을 비교하면, 입력과 필터의
`1`이 같은 위치에 많을수록 `1×1`이 많이 생겨 점수가 커집니다. 따라서 두
필터 중 더 큰 점수를 받은 모양을 더 유사하다고 판단합니다.

MAC 점수는 확률이 아닙니다. 음수나 서로 다른 범위의 값을 비교할 때는 단순히
점수가 크다는 이유만으로 더 유사하다고 판단하면 안 됩니다.

## 5. 사용자 입력 모드

다음 값을 순서대로 입력합니다.

```text
필터 A: Cross
0 1 0
1 1 1
0 1 0

필터 B: X
1 0 1
0 1 0
1 0 1

입력 패턴: X
1 0 1
0 1 0
1 0 1
```

실행 결과의 형태는 다음과 같습니다. 시간은 컴퓨터 상태에 따라 달라집니다.

```text
[MAC 결과]
A 점수: 1
B 점수: 5
평균 연산 시간(10회): 0.005000 ms
판정: B

[성능 분석: 크기별 10회 평균]
크기       평균 시간(ms)       연산 횟수(N²)
3×3            0.005000                  9
```

### 잘못 입력하면 어떻게 되나요?

`main.py`의 `read_matrix()`는 한 줄에 숫자가 3개 있는지 확인합니다.

- 숫자가 2개 또는 4개이면 같은 행을 다시 입력합니다.
- `a`처럼 숫자가 아닌 값을 입력해도 같은 행을 다시 입력합니다.
- 입력을 취소하려면 `Ctrl+C`를 누릅니다.
- `Ctrl+C` 또는 EOF가 발생해도 오류 추적을 보여주지 않고 안전하게 종료합니다.

## 6. `data.json` 분석 모드

`data.json`은 크게 `filters`와 `patterns`로 나뉩니다.

```text
filters
├── size_5
│   ├── cross
│   └── x
├── size_13
└── size_25

patterns
├── size_5_1
├── size_13_1
└── size_{N}_{idx}
```

### 패턴 키 규칙

패턴 키는 `size_{N}_{idx}` 형식입니다.

```text
size_13_2
     │  └─ 두 번째 패턴
     └──── 13×13 크기
```

`analysis.py`의 `extract_size()`가 N을 꺼냅니다. 그다음
`load_filter_group()`이 `filters.size_N`에서 같은 크기의 필터를 찾습니다.

| 패턴 키 | 결과 |
| --- | --- |
| `size_5_1` | N=5, `filters.size_5` 사용 |
| `size_25_2` | N=25, `filters.size_25` 사용 |
| `size5_1` | 키 형식 오류 |
| `size_5` | 순번이 없어 오류 |

키에 적힌 N과 실제 패턴·필터의 행렬 크기도 같은지 확인합니다.

### 라벨 정규화

같은 의미를 여러 문자열로 표현할 수 있습니다.

| JSON 표현 | 프로그램 내부 라벨 |
| --- | --- |
| `+`, `cross`, `Cross` | `Cross` |
| `x`, `X` | `X` |

`npu.py`의 `normalize_label()`이 이 변환을 담당합니다. 문자열 변환을 MAC
계산과 분리하면 JSON 표현이 달라져도 계산 코드를 바꾸지 않아도 됩니다.
지원하지 않는 라벨은 추측하지 않고 해당 케이스를 `ERROR/FAIL`로 기록합니다.

## 7. 부동소수점과 epsilon

컴퓨터는 `0.1` 같은 십진 실수 중 일부를 이진수로 정확하게 저장하지 못합니다.
곱셈과 덧셈이 반복되면 수학적으로 같은 점수에도 매우 작은 차이가 생길 수
있습니다.

```text
Cross 점수: 0.9
X 점수:     0.8999999999999999
차이:       약 1.11e-16
```

이 작은 차이를 실제 승패로 판단하지 않도록 다음 규칙을 사용합니다.

```text
abs(Cross 점수 - X 점수) < 1e-9
→ UNDECIDED
```

- 사용자 입력 모드: 쉬운 한국어인 `판정 불가`로 출력
- JSON 분석 모드: 내부 표준값 `UNDECIDED`로 출력
- JSON의 expected는 Cross 또는 X이므로 UNDECIDED는 불일치하여 FAIL로 집계

두 모드의 계산 규칙은 같습니다. 사용자에게 보여주는 문구와 JSON의 후속
PASS/FAIL 처리만 다릅니다.

## 8. 결과 리포트

현재 `data.json`의 실행 결과는 총 6개, PASS 3개, FAIL 3개입니다.

```text
[결과 요약]
총 테스트: 6개
통과: 3개
실패: 3개

실패 케이스:
- size_5_1: epsilon 내 동점으로 UNDECIDED
- size_13_2: epsilon 내 동점으로 UNDECIDED
- size_25_1: epsilon 내 동점으로 UNDECIDED
```

실패 원인과 복잡도 분석:

1. `size_5_2`, `size_13_1`, `size_25_2`는 판정과 expected가 같아 PASS입니다.
2. `size_5_1`의 두 점수 차이는 약 `1.11e-16`입니다.
3. 이 차이는 epsilon `1e-9`보다 작아 `UNDECIDED`입니다.
4. expected는 X이므로 UNDECIDED와 달라 FAIL입니다.
5. `size_13_2`도 두 점수 차이가 약 `2.66e-15`인 사실상 동점입니다.
6. `size_25_1`도 두 점수 차이가 약 `1.78e-15`인 사실상 동점입니다.
7. 세 FAIL은 JSON 문법이나 행렬 크기 오류가 아닙니다.
8. 세 FAIL은 작은 실수 차이를 승패로 보지 않는 epsilon 정책의 결과입니다.
9. 데이터 오류는 `ERROR`, 정상 계산 후 예상과 다르면 `FAIL`로 구분합니다.
10. MAC은 N×N의 모든 위치 N²개를 한 번씩 확인합니다.
11. 따라서 시간 복잡도는 O(N²)이고 핵심 계산의 추가 공간은 O(1)입니다.
12. 실행 시간은 운영체제 부하와 Python 환경 때문에 N² 비율과 정확히 같지는 않습니다.

JSON 케이스의 FAIL은 과제 평가의 FAIL과 뜻이 다릅니다. JSON FAIL은 해당
패턴의 판정과 expected가 다르다는 뜻이고, 과제 평가는 이 규칙을 올바르게
구현하고 설명했는지를 판단합니다.

## 9. 시간 측정과 O(N²)

`measure_mac_time()`은 다음 경계를 사용합니다.

```text
행렬 준비와 워밍업       ← 측정하지 않음
시작 시간 기록
mac_score() 10회 실행    ← 측정 구간
종료 시간 기록
화면 출력                ← 측정하지 않음
```

따라서 파일 읽기, 사용자 입력, 패턴 생성과 화면 출력은 MAC 연산 시간에
포함되지 않습니다.

| 크기 | 위치 수 N² |
| ---: | ---: |
| 3×3 | 9 |
| 5×5 | 25 |
| 13×13 | 169 |
| 25×25 | 625 |
| 1000×1000 | 1,000,000 |

N×N 행렬에는 N²개의 위치가 있고 `mac_score()`는 각 위치를 한 번 방문합니다.
각 위치에서 곱셈과 덧셈을 한 번 하므로 시간 복잡도는 O(N²)입니다. Cross와 X
두 필터를 계산하면 약 `2N²`이지만 빅오에서는 상수 2를 제외합니다.

## 10. 실패 원인 진단

실패하면 다음 순서로 확인합니다.

```text
1. JSON과 행렬이 계산 가능한가?
2. 손으로 계산한 MAC 점수와 같은가?
3. 두 점수의 차이가 epsilon보다 작은가?
```

| 분류 | 예시 | 확인할 함수 | 개선 방법 |
| --- | --- | --- | --- |
| 데이터·스키마 | 잘못된 JSON, 키, 라벨, 행렬 크기 | `load_json_file()`, `extract_size()`, `load_filter_group()` | 해당 데이터 수정 |
| 로직 | 손계산과 점수가 다름, 낮은 점수가 선택됨 | `mac_score()`, `classify()` | 작은 예제와 단위 테스트로 계산 확인 |
| 수치 비교 | 거의 같은 점수가 서로 다르게 판정됨 | `compare_scores()` | 점수 차이와 epsilon 확인 |

한 패턴에 데이터 오류가 있어도 `analyze_dataset()`은 그 케이스만
`ERROR/FAIL`로 기록하고 다음 패턴을 계속 분석합니다. 파일 자체를 읽을 수
없거나 최상위 `filters`·`patterns`가 없을 때만 전체 분석을 중단합니다.

## 12. 평가 질문 빠른 답변

| 질문 | 답변 핵심 |
| --- | --- |
| MAC이 무엇인가요? | 같은 위치의 값을 곱해 모두 더하는 연산이며 AI의 가중합과 행렬 계산의 기초입니다. |
| 왜 높은 점수가 더 유사한가요? | 같은 크기·범위의 0/1 데이터에서는 활성 위치가 많이 겹칠수록 `1×1`의 합이 커집니다. |
| 필터를 어떻게 찾나요? | `size_{N}_{idx}`에서 N을 꺼내 `filters.size_N`을 선택합니다. |
| 라벨을 왜 정규화하나요? | `+`와 `cross`처럼 같은 의미의 문자열을 Cross 하나로 바꿔 계산 로직을 단순하게 유지합니다. |
| epsilon이 왜 필요한가요? | 부동소수점의 아주 작은 표현 오차를 실제 승패로 잘못 판단하지 않기 위해서입니다. |
| 모드별 동점이 다른가요? | 내부 판정은 모두 UNDECIDED이고 사용자 문구와 JSON의 PASS/FAIL 처리만 다릅니다. |
| 왜 O(N²)인가요? | N×N의 N²개 위치를 이중 반복문으로 한 번씩 방문하기 때문입니다. |
| I/O를 어떻게 제외했나요? | 준비와 출력은 타이머 밖에 두고 `mac_score()` 반복만 측정합니다. |

## 13. 심층 질문

### 새 라벨 `o`를 추가한다면

다음 순서로 확장합니다.

1. `normalize_label()`에 `o` → `O` 규칙을 추가합니다.
2. `data.json`의 각 `filters.size_N`에 O 필터를 추가합니다.
3. `classify()`가 세 라벨의 점수를 비교하도록 바꿉니다.
4. 결과 출력이 모든 라벨의 점수를 보여주도록 바꿉니다.
5. O 정규화, O 최고점, 동점, 필터 누락 테스트를 추가합니다.
6. 기존 Cross/X 테스트도 실행해 이전 기능이 깨지지 않았는지 확인합니다.

### 1000×1000 패턴을 처리한다면

한 필터당 100만 위치, 두 필터면 약 200만 위치를 계산합니다. Python의 중첩
목록과 숫자 객체도 메모리를 많이 사용합니다.

최적화 전에 같은 입력으로 시간, 메모리, 결과값을 기록합니다. 그다음 연속
배열, 블록 처리, 필터 재사용, 멀티프로세싱 순으로 하나씩 적용하고 전후 값을
비교합니다. 과제의 현재 코드는 최적화보다 원리를 쉽게 읽는 것을 우선합니다.

### CPU와 NPU의 병목

| 현재 Python CPU 실행 | 실제 NPU 실행 |
| --- | --- |
| Python 반복문과 함수 호출이 느림 | 연산 장치로 데이터를 옮기는 시간이 큼 |
| 캐시에 맞지 않는 메모리 접근 | 외부 메모리 대역폭과 온칩 버퍼가 제한됨 |
| 연속 배열·블록 처리로 개선 | 타일링·배치·필터 재사용으로 개선 |

이 프로젝트의 측정값은 CPU에서 Python으로 실행한 결과이며 실제 NPU의 성능
수치가 아닙니다.

## 14. 테스트 범위

`tests/`는 다음을 확인합니다.

- 정사각형 행렬과 숫자 값 검증
- Cross/X 라벨 정규화
- MAC 손계산 결과
- epsilon 동점 판정
- 사용자 입력 오류 후 재입력
- `Ctrl+C` 안전 종료
- JSON 키와 필터 크기 검증
- 잘못된 케이스의 오류 격리
- 기본 데이터의 6개/3 PASS/3 FAIL 결과
- 크기별 N² 연산 횟수

테스트는 구현을 복잡하게 만들기 위한 것이 아니라, 코드를 단순하게 바꿔도
평가에 필요한 동작이 그대로 유지되는지 확인하기 위한 안전장치입니다.
