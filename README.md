# Mini NPU Simulator

Python의 기초 문법으로 MAC 연산을 직접 만들어 보는 프로젝트입니다.

클래스나 외부 라이브러리를 사용하지 않았습니다. 초보자가 흐름을 따라갈 수
있도록 **리스트, 딕셔너리, 반복문, 조건문, 작은 함수**로 구성했습니다.

## 1. 실행 방법

Python 3.8 이상이 필요합니다.

```bash
python3 main.py
```

실행하면 다음 메뉴가 나옵니다.

```text
1. 사용자 입력 (3×3)
2. data.json 분석
3. 보너스: 2차원/1차원 성능 비교
0. 종료
```

자동 테스트는 다음 명령으로 실행합니다.

```bash
python3 -m unittest discover -v
```

## 2. 파일 구조

```text
.
├── main.py               # 메뉴와 전체 시작점
├── user_mode.py          # 3×3 사용자 입력과 재입력
├── json_mode.py          # JSON 읽기, 검증, 판정, 요약
├── mac.py                # MAC, 점수 비교, 라벨, 패턴 생성
├── performance.py        # 시간 측정, 성능표, 보너스 비교
├── data.json             # 5×5, 13×13, 25×25 데이터
├── tests/                # 31개 자동 테스트
└── README.md
```

기능별로 파일을 나눈 이유는 수정할 곳을 쉽게 찾기 위해서입니다. 계산 공식을
바꾸려면 `mac.py`, 입력 문구를 바꾸려면 `user_mode.py`, JSON 규칙을 바꾸려면
`json_mode.py`를 보면 됩니다.

## 3. 프로그램 흐름

### 모드 1: 사용자 입력

```text
필터 A 3줄 입력
→ 필터 B 3줄 입력
→ 패턴 3줄 입력
→ A와 B의 MAC 점수 계산
→ epsilon으로 점수 비교
→ 점수, 시간(ms), A/B/판정 불가 출력
```

입력 예시는 다음과 같습니다.

```text
필터 A
0 1 0
1 1 1
0 1 0

필터 B
1 0 1
0 1 0
1 0 1

입력 패턴
1 0 1
0 1 0
1 0 1
```

결과 예시는 다음과 같습니다. 시간은 컴퓨터 상태에 따라 달라집니다.

```text
A 점수: 1
B 점수: 5
평균 연산 시간(10회): 0.005385 ms
판정: B
```

한 줄의 숫자가 3개가 아니거나 숫자로 바꿀 수 없는 값이면 같은 행을 다시
입력받습니다. 입력을 그만두려면 `Ctrl+C`를 누르면 됩니다.

### 모드 2: data.json 분석

```text
data.json 읽기
→ 패턴 키에서 N 추출
→ filters의 size_N 선택
→ 행렬 크기와 라벨 확인
→ Cross와 X의 MAC 점수 계산
→ expected와 비교해 PASS/FAIL 출력
→ 크기별 성능표와 전체 요약 출력
```

한 케이스의 데이터가 잘못되어도 프로그램 전체가 멈추지 않습니다. 해당
케이스만 `ERROR/FAIL`로 저장하고 다음 패턴을 계속 분석합니다.

## 4. MAC 연산 원리

MAC은 **Multiply-Accumulate**, 즉 “곱하고 누적해서 더하기”입니다.

입력 패턴과 필터의 같은 위치에 있는 값을 곱한 후 모든 결과를 더합니다.

```text
입력 패턴        Cross 필터
0 1 0            0 1 0
1 1 1      ×     1 1 1
0 1 0            0 1 0

점수 = 0 + 1 + 0 + 1 + 1 + 1 + 0 + 1 + 0 = 5
```

`mac.py`의 핵심은 두 겹의 반복문입니다.

```python
total = 0.0

for row in range(pattern_size):
    for column in range(pattern_size):
        multiplied_value = (
            pattern[row][column] * filter_matrix[row][column]
        )
        total = total + multiplied_value
```

현재 데이터처럼 0과 1의 범위가 같은 두 필터를 비교할 때, `1×1`이 많이
겹칠수록 점수가 커집니다. 그래서 더 높은 점수의 필터와 더 비슷하다고
판단할 수 있습니다.

AI의 신경망도 입력값과 가중치를 곱하고 더하는 일을 매우 많이 반복합니다.
따라서 MAC은 이미지 인식과 행렬 계산의 기초이며, NPU는 많은 MAC을 병렬로
빠르게 처리하도록 만든 장치입니다.

## 5. data.json 규칙

### 키 규칙

패턴 키는 `size_{N}_{idx}` 형식입니다.

```text
size_13_2
     │  └─ 두 번째 패턴
     └──── 13×13 크기
```

`json_mode.py`의 `get_size_from_key()`는 `_`를 기준으로 키를 나누고 N을
꺼냅니다. `size_13_2`라면 `filters`의 `size_13`을 선택합니다.

### 라벨 규칙

JSON과 프로그램이 같은 뜻을 다른 글자로 표현할 수 있습니다.

| JSON 표현 | 프로그램 표준 라벨 |
| --- | --- |
| `+`, `cross`, `Cross` | `Cross` |
| `x`, `X` | `X` |

`mac.py`의 `normalize_label()`이 이 값을 통일합니다. 정규화를 하지 않으면
`+`와 `Cross`가 같은 뜻인데도 문자열이 다르다는 이유로 FAIL이 생길 수
있습니다. 지원하지 않는 라벨은 마음대로 추측하지 않고 오류로 처리합니다.

## 6. 부동소수점과 epsilon

컴퓨터는 일부 실수를 정확하게 저장하지 못합니다. 예를 들어 수학적으로 거의
같은 값이 아래처럼 저장될 수 있습니다.

```text
0.9000000000000000
0.8999999999999999
```

단순히 `>`로 비교하면 첫 번째 값이 이기지만, 차이는 약 `1.11e-16`으로 매우
작습니다. 그래서 다음 정책을 사용합니다.

```text
abs(A 점수 - B 점수) < 1e-9
→ 사실상 동점
```

- 사용자 입력 모드에서는 `판정 불가`로 보여 줍니다.
- JSON 모드에서는 내부 판정값 `UNDECIDED`로 보여 줍니다.
- expected는 Cross 또는 X이므로 UNDECIDED는 FAIL로 집계됩니다.

두 모드의 계산 정책은 같고, 사용하는 사람에게 보여 주는 문구만 다릅니다.

## 7. 성능과 O(N²)

`performance.py`는 파일 읽기와 화면 출력을 타이머 밖에 둡니다. 타이머 안에는
MAC 함수 호출만 넣고, 각 크기를 10회 반복한 뒤 평균 시간을 ms로 출력합니다.

| 크기 | 곱셈 위치 수 |
| --- | ---: |
| 3×3 | 9 |
| 5×5 | 25 |
| 13×13 | 169 |
| 25×25 | 625 |

N개의 행과 N개의 열을 모두 방문하므로 연산 횟수는 `N × N = N²`입니다.
따라서 시간 복잡도는 **O(N²)**입니다. 실제 측정 시간은 운영체제 부하와
Python 실행 환경의 영향을 받으므로 N² 비율과 정확히 같지는 않습니다.

## 8. 결과 리포트

현재 첨부된 `data.json`의 결과는 **총 6개, PASS 3개, FAIL 3개**입니다.

```text
총 테스트: 6개
통과: 3개
실패: 3개

실패 케이스:
- size_5_1: epsilon 범위 안의 동점
- size_13_2: epsilon 범위 안의 동점
- size_25_1: epsilon 범위 안의 동점
```

실패 원인과 복잡도 분석:

1. `size_5_2`, `size_13_1`, `size_25_2`는 판정과 expected가 같아 PASS입니다.
2. `size_5_1`의 두 점수 차이는 약 `1.11e-16`입니다.
3. 이 차이는 epsilon `1e-9`보다 작아 `UNDECIDED`입니다.
4. `size_13_2`도 점수 차이가 약 `2.66e-15`인 사실상 동점입니다.
5. `size_25_1`도 점수 차이가 약 `1.78e-15`인 사실상 동점입니다.
6. expected는 Cross 또는 X이므로 세 UNDECIDED는 FAIL로 집계됩니다.
7. 이 세 FAIL은 JSON 문법이나 행렬 크기가 잘못된 데이터 오류가 아닙니다.
8. 이 세 FAIL은 작은 실수 차이를 승패로 만들지 않는 수치 비교 정책의 결과입니다.
9. 키·라벨·크기가 잘못되면 `데이터/스키마 오류`로 따로 기록합니다.
10. 정상 계산 후 expected와 다르면 `로직/예상 불일치`로 구분할 수 있습니다.
11. MAC은 N×N의 모든 위치를 한 번씩 방문하므로 연산 횟수는 N²입니다.
12. 두 겹의 반복문 때문에 시간 복잡도는 O(N²)입니다.
13. 핵심 계산은 누적값과 반복문 위치만 사용하므로 추가 작업 공간은 O(1)입니다.
14. 측정값이 이론 비율과 정확히 같지 않은 이유는 시스템 부하와 상수 시간 때문입니다.

## 9. 실패 문제를 찾는 순서

실패가 나오면 다음 순서로 확인합니다.

1. **데이터/스키마 문제:** 키가 `size_{N}_{idx}`인지, 필터와 패턴 크기가
   같은지, Cross와 X 필터가 모두 있는지 확인합니다.
2. **로직 문제:** 같은 위치끼리 곱했는지, 두 점수를 올바른 라벨 이름으로
   비교했는지 확인합니다.
3. **수치 비교 문제:** 두 점수 차이가 epsilon보다 작은지 확인합니다.

이 순서로 보면 데이터 문제와 계산 문제를 섞지 않고 설명할 수 있습니다.

## 10. 보너스 과제

보너스 두 가지를 모두 구현했습니다.

### 패턴 자동 생성

`make_pattern(size, label)`은 원하는 크기의 Cross 또는 X를 만듭니다. 성능
분석에서도 이 함수를 재사용하므로 크기별 테스트 데이터를 직접 반복해서
작성할 필요가 없습니다.

### 2차원과 1차원 MAC 비교

`flatten_matrix()`가 N×N 행렬을 길이 N²의 1차원 리스트로 바꿉니다.
`calculate_mac_1d()`는 한 겹의 반복문으로 같은 계산을 합니다.

메뉴 3번은 같은 25×25 입력과 같은 10회 반복 조건에서 두 방법을 비교합니다.
두 점수가 같아야 변환 전후의 계산이 올바른 것입니다. 시간은 실행할 때마다
달라지므로 어느 방식이 항상 더 빠르다고 단정하지 않고 실제 측정값을 봅니다.

## 11. 평가 질문 바로 답하기

**Q. MAC은 무엇인가요?**

A. 입력과 필터의 같은 위치를 곱하고, 곱한 값을 모두 더하는 연산입니다.

**Q. 왜 높은 점수를 더 비슷하다고 보나요?**

A. 같은 범위의 0/1 데이터에서는 입력과 필터의 1이 많이 겹칠수록 1×1이
많아져 점수가 커지기 때문입니다.

**Q. 라벨을 왜 정규화하나요?**

A. `+`와 `cross`처럼 모양은 달라도 같은 뜻인 값을 Cross라는 한 이름으로
비교하기 위해서입니다.

**Q. 왜 epsilon이 필요한가요?**

A. 부동소수점 저장 과정의 아주 작은 오차를 실제 승패로 잘못 판단하지 않기
위해서입니다.

**Q. 왜 O(N²)인가요?**

A. N개의 행마다 N개의 열을 확인해서 전체 N²개 위치를 한 번씩 계산하기
때문입니다.

**Q. I/O 시간은 왜 제외했나요?**

A. 키보드 입력, 파일 읽기, 화면 출력 속도가 아니라 MAC 계산 자체의 시간을
비교하기 위해서입니다.

**Q. 1000×1000이면 무엇이 문제인가요?**

A. 한 필터만 계산해도 100만 번 곱해야 하고 Python 리스트는 메모리도 많이
사용합니다. 먼저 1차원 연속 데이터, 블록 처리, 불필요한 복사를 줄이고, 실제
제품에서는 NumPy나 NPU 같은 병렬 처리 도구를 검토할 수 있습니다.

**Q. CPU와 NPU의 차이는 무엇인가요?**

A. CPU의 Python 반복문은 주로 계산을 순서대로 처리합니다. NPU는 많은 MAC을
동시에 처리하지만 데이터를 장치로 옮기는 시간이 새 병목이 될 수 있습니다.

## 12. 새 라벨을 추가한다면

예를 들어 `O` 모양을 추가할 때는 다음 순서를 지킵니다.

1. `normalize_label()`에 O의 외부 표현과 표준 이름을 추가합니다.
2. `data.json`의 각 `size_N`에 O 필터를 추가합니다.
3. 두 후보만 비교하던 판정을 여러 점수 중 최대값을 찾도록 바꿉니다.
4. 사용자 화면과 JSON 결과에 O가 출력되게 합니다.
5. O 정규화, O 판정, 동점, 잘못된 O 데이터 테스트를 추가합니다.

정규화 → 판정 → 출력 → 테스트 순서로 바꾸면 빠뜨린 기능을 찾기 쉽습니다.
