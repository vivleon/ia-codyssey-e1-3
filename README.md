# Mini NPU Simulator

AI 전용 칩이 반복 수행하는 MAC(Multiply-Accumulate) 연산을 Python 반복문으로
직접 구현한 콘솔 애플리케이션입니다. 3×3 사용자 입력과 5×5, 13×13,
25×25 JSON 패턴을 처리하고, 크기별 실행 시간과 `N²` 연산 횟수를
비교합니다.

## 실행 환경

- Python 3.8 이상
- 외부 라이브러리 없음
- 사용 표준 라이브러리: `argparse`, `dataclasses`, `json`, `pathlib`,
  `re`, `time`, `typing`, `unittest`
- 구현·검증 환경: Python 3.13.12

## 실행 방법

저장소를 복제한 뒤 프로젝트 루트에서 실행합니다.

```bash
git clone https://github.com/vivleon/ia-codyssey-e1-3.git
cd ia-codyssey-e1-3
python3 main.py
```

메뉴에서 실행 방식을 선택합니다.

```text
1. 사용자 입력 (3×3)
2. data.json 분석
```

메뉴를 생략하거나 반복 측정 횟수와 JSON 경로를 지정할 수도 있습니다.
반복 횟수는 최소 10회입니다.

```bash
python3 main.py --mode user
python3 main.py --mode json
python3 main.py --mode json --data ./data.json --repeats 100
```

자동 테스트:

```bash
python3 -m unittest discover -v
```

## 사용자 입력 모드

필터 A, 필터 B, 입력 패턴을 각각 세 줄씩 입력합니다. 한 줄에는 공백으로
구분한 숫자 세 개가 있어야 합니다.

```text
# 필터 A: Cross
0 1 0
1 1 1
0 1 0

# 필터 B: X
1 0 1
0 1 0
1 0 1

# 입력 패턴: X
1 0 1
0 1 0
1 0 1
```

이 입력의 A 점수는 `1`, B 점수는 `5`이므로 결과는 `B`입니다. 열 수가
다르거나 숫자로 변환할 수 없는 값을 입력하면 같은 행을 다시 입력하도록
안내합니다. Ctrl+C 또는 EOF가 발생해도 예외 추적을 노출하지 않고
안전하게 종료합니다.

## 구현 요약

### 데이터 구조

`Matrix` 클래스가 임의 크기의 정사각 2차원 배열을 저장합니다. `get()`과
`set()`으로 특정 위치를 읽고 쓸 수 있으며, 비정사각 행렬과 숫자가 아닌
값을 생성 시점에 거부합니다. 3×3, 5×5, 13×13, 25×25를 같은 코드로
처리합니다.

### MAC 연산

`mac_score()`는 두 겹의 `for` 반복문으로 같은 위치의 패턴 값과 필터 값을
곱하고 `total`에 누적합니다. NumPy, pandas 또는 다른 벡터화 라이브러리는
사용하지 않습니다.

### 라벨 정규화

JSON의 표현과 내부 판정 표현을 분리합니다.

| JSON 값 또는 키 | 내부 표준 라벨 |
| --- | --- |
| `+`, `cross` | `Cross` |
| `x` | `X` |

콘솔 출력과 PASS/FAIL 비교는 `Cross`, `X` 표준 라벨만 사용합니다.
지원하지 않는 라벨은 해당 케이스의 스키마 오류로 기록됩니다.

### epsilon 동점 정책

두 점수의 차이가 `abs(Cross - X) < 1e-9`이면 아주 작은 부동소수점
표현 차이를 우열로 해석하지 않고 `UNDECIDED`로 판정합니다. 점수 차이가
epsilon 이상일 때만 더 높은 점수의 라벨을 선택합니다.

### 오류 격리

JSON 파일 자체가 없거나 손상되면 이해할 수 있는 메시지와 함께 분석을
중단합니다. 개별 패턴의 키, 라벨, 행렬 크기 또는 필터가 잘못된 경우에는
그 케이스만 `ERROR/FAIL`로 기록하고 나머지 케이스 분석을 계속합니다.

## data.json 구조

```text
filters
├── size_5
│   ├── cross
│   └── x
├── size_13
└── size_25

patterns
├── size_5_1
│   ├── input
│   └── expected
└── size_{N}_{idx}
```

프로그램은 패턴 키의 `N`을 읽어 `filters.size_N`을 선택하고, 패턴과 두
필터가 모두 정확히 N×N인지 검증합니다. 총 테스트 수는 문서에 고정하지
않고 `patterns`의 실제 항목 수에서 계산합니다.

## 결과 리포트

첨부된 `data.json`을 100회 반복 측정으로 실행한 결과입니다. 실행 시간은
기기 상태에 따라 달라질 수 있습니다.

| 크기 | 평균 시간(ms) | 연산 횟수(N²) |
| --- | ---: | ---: |
| 3×3 | 0.002600 | 9 |
| 5×5 | 0.006554 | 25 |
| 13×13 | 0.041740 | 169 |
| 25×25 | 0.151733 | 625 |

실제 데이터 판정은 총 6개, PASS 3개, FAIL 3개입니다.

1. `size_5_2`, `size_13_1`, `size_25_2`는 판정과 expected가 같아 PASS입니다.
2. `size_5_1`은 Cross `0.9`, X `0.8999999999999999`로 계산됩니다.
3. 이 차이는 약 `1.11e-16`이므로 epsilon `1e-9`보다 작아 `UNDECIDED`입니다.
4. `size_5_1`의 expected는 X이므로 비교 결과는 FAIL입니다.
5. `size_13_2`는 Cross `7.499999999999997`, X `7.5`로 사실상 동점입니다.
6. `size_13_2`의 expected는 Cross지만 epsilon 정책상 `UNDECIDED`여서 FAIL입니다.
7. `size_25_1`도 Cross `4.9`, X `4.899999999999999`로 사실상 동점입니다.
8. `size_25_1`의 expected는 X지만 같은 정책으로 `UNDECIDED`가 되어 FAIL입니다.
9. 세 실패는 키·행렬 크기·라벨 스키마 오류가 아니라 데이터의 동점 설계와
   expected 라벨 사이의 정책 불일치입니다.
10. 아주 작은 실수 차이만 보고 X 또는 Cross를 고르면 실행 환경과 누적
    순서에 따라 결과가 바뀔 수 있으므로 epsilon 정책을 유지했습니다.
11. 스키마 문제는 `ERROR`, 정상 계산 후 예상과 다른 문제는 `FAIL`로
    분리하여 데이터 문제와 로직 문제를 구별할 수 있게 했습니다.
12. 따라서 3 FAIL은 숨기거나 강제로 expected에 맞추지 않은, 명세의
    동점 규칙을 그대로 적용한 재현 가능한 결과입니다.

### 시간 복잡도 분석

N×N 행렬에는 N²개의 위치가 있습니다. `mac_score()`는 모든 위치를 정확히
한 번 방문하고 각 위치에서 곱셈 한 번과 누적 덧셈 한 번을 수행하므로
시간 복잡도는 **O(N²)**, 추가 작업 공간은 **O(1)**입니다. 측정표에서도
연산 위치가 9 → 25 → 169 → 625로 증가할수록 평균 실행 시간이 전반적으로
증가합니다. 짧은 작업은 운영체제 스케줄링과 타이머 잡음의 영향을 받으므로
각 크기를 최소 10회 반복하고 평균값을 사용합니다. 파일 읽기와 콘솔 출력은
측정 구간에서 제외하고 `mac_score()` 호출만 측정합니다.
